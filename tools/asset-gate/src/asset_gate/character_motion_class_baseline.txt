# Documented pre-T-0357 motion-class gaps for the character motion-class
# declaration sweep (T-0357, Codex review 2026-09-11 finding 2).
#
# Paths are relative to the assets/final/ root, forward slashes.
#
# T-0357 requires every character-generation output to declare a validated
# motion_class (idle/locomotion/transition/loop). Before this card, NONE of
# the committed character sidecars recorded one at all -- an absent class
# silently rode the same skip/pass path a deliberately-idle sheet legitimately
# uses in every downstream check (character.py's own T-0271/T-0340 module
# notes), so nothing ever actually required a sheet to say what it is. These
# sidecars are exempted here because they predate the requirement entirely
# and their real classification was never recorded -- the same historical-gap
# shape character_arm_c_baseline.txt already documents for CHR-1's own
# fields. This list is expected to shrink to ZERO as each sheet is
# regenerated (picking up motion_class on merit) or has it genuinely
# backfilled by a dedicated follow-up card, never grown to silence a fresh
# violation.
#
# T-0359 backfilled `motion_class` on 11 of the original 18 sidecars listed
# here (the ones with an unambiguous idle-generation record -- each one's own
# `generator` field names an idle-specific script, e.g.
# `gen_arm_a_idle_T0228.py`, `gen_hybrid_idle_T0252.py`) and removed them
# from this list; they now pass `character_motion_class_declared` on merit
# (`motion_class: "idle"`, justified in each sidecar's own new
# `motion_class_basis` field), not via this exemption. The 6 remaining
# non-walk entries below (`player_crouch_hide_sheet_*`,
# `player_die_sheet_*`, `player_move_sheet_*`) are deliberately left
# baselined: their own `synth_states.py` prompts describe real per-frame
# motion (a crouch/hide descent, a death sequence, a stride cycle), which
# would classify as `transition`/`locomotion`, not `idle` -- but none of them
# carry the `layout`/`frame_generation` rig evidence T-0357's own recompute
# requires, so labelling them accurately would immediately fail them for
# missing rig evidence, a new, unreviewed CI-red consequence beyond this
# card's own explicitly-reviewed walk exemption below. That classification
# call (and whether these old synthetic T-0199 fixtures are even meant to be
# held to the T-0340 bar) is left to a dedicated follow-up card. `pose_grid_stage3_T0218`
# is also left baselined -- its own generator field names a ComfyUI workflow
# JSON with no frame-sequence/motion description to classify from.
#
