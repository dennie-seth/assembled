# Documented pre-T-0357 motion-class gaps for the character motion-class
# declaration sweep (T-0357, Codex review 2026-09-11 finding 2).
#
# Paths are relative to the assets/final/ root, forward slashes.

# T-0357 requires every character-generation output to declare a validated
# motion_class (idle/locomotion/transition/loop). Before this card, NONE of
# the committed character sidecars recorded one at all -- an absent class
# silently rode the same skip/pass path a deliberately-idle sheet legitimately
# uses in every downstream check (character.py's own T-0271/T-0340 module
# notes), so nothing ever actually required a sheet to say what it is. These
# sidecars are exempted here because they predate the requirement entirely
# and their real classification was never recorded -- the same historical-gap
# shape character_arm_c_baseline.txt already documents for CHR-1's own
# fields. This list is expected to shrink to ZERO as each sheet is
# regenerated (picking up motion_class on merit) or has it genuinely
# backfilled by a dedicated follow-up card, never grown to silence a fresh
# violation.
#
# T-0359 backfilled `motion_class` on all 18 of the non-walk sidecars
# originally listed here and removed every one of them from this list; they
# now pass `character_motion_class_declared` on merit (justified in each
# sidecar's own new `motion_class_basis` field), not via this exemption:
#   - 11 idle sheets whose own `generator` field names an idle-specific
#     script (e.g. `gen_arm_a_idle_T0228.py`, `gen_hybrid_idle_T0252.py`) ->
#     `motion_class: "idle"`.
#   - `pose_grid_stage3_T0218` -> `motion_class: "idle"` too: its own
#     `prompt_positive` describes 9 figures "standing upright facing
#     forward" with no frame-to-frame pose progression (its `negative_prompt`
#     excludes "action pose"), and it is the ControlNet conditioning input
#     for `player_idle_sheet_stage3_sdxl_T0218` -- itself labelled `idle` by
#     this same card. A static standing reference grid depicts no motion, so
#     it is idle, not unclassifiable, even though (like the round-1 bake-off
#     arms above) it carries no `frame_delta_range` of its own -- that gap is
#     `character_arm_c_baseline.txt`'s CHR-1 concern, not this file's.
#   - `player_crouch_hide_sheet_v1`/`v2` -> `motion_class: "transition"`:
#     each sidecar's own prompt/`layout.frame_cells` describes a
#     one-directional, non-repeating descent from standing to fully
#     crouched/hidden -- real per-frame pose progression, but not a
#     repeating gait, so `transition`, not `idle` or `locomotion`.
#   - `player_die_sheet_v1`/`v2` -> `motion_class: "transition"`: each
#     sidecar's own prompt/`layout.frame_cells` describes a one-directional,
#     non-repeating fall from standing to prone/collapsed -- a terminal
#     transition, not a loop.
#   - `player_move_sheet_v1`/`v2` -> `motion_class: "locomotion"`: each
#     sidecar's own prompt explicitly names it a walk cycle with alternating
#     left/right leg stride, the same repeating-gait category as
#     `player_walk_sheet_hybrid.provenance.json` below.
#
# Labelling the 6 `player_crouch_hide_sheet_*`/`player_die_sheet_*`/
# `player_move_sheet_*` sidecars accurately makes `character_motion_fidelity`
# FAIL on all 6 -- none of them carry the `frame_generation` rig-keypoint
# evidence T-0357's own recompute requires, so each now fails with
# `missing_rig_evidence` naming that gap explicitly. That is the correct,
# intended outcome of an accurate label, not a defect: this card's job is to
# make the gate state each sheet's real condition, never to keep it quiet by
# leaving an honestly-classifiable sheet unlabelled. See the verbatim gate
# output below for the exact FAIL lines this produces.
