## Context

`docs/design/13-asset-pipeline.md` §6.8 splits key art from concept
sheets: key art (`assets/src/keyart/`) sells direction to humans and is
committed/versioned but is **not** a pipeline input and carries no
provenance hash; concept sheets (`assets/src/concept/`) are flat side-on
and **feed** the pipeline (IP-Adapter/img2img conditioning, T-0105 palette
extraction, `concept_hash` in provenance).

`tools/comfy-client/src/comfy_client/concept.py` (T-0104) currently only
knows one mode, and writes everything to `assets/src/concept/` with a
`concept_hash` provenance sidecar. The two Signal Tower sheets produced
under that path were assessed as key art, not concept sheets (see
`13-asset-pipeline.md` §6.10), and were manually relocated to
`assets/src/keyart/` — this task is to make the tooling enforce the split
going forward instead of relying on a human to notice and `git mv` after
the fact.

## Acceptance

- [ ] `generate_concept` (or a sibling entrypoint) takes an explicit mode
      — `keyart` vs. `concept` — rather than always targeting
      `assets/src/concept/`
- [ ] `keyart` mode writes to `assets/src/keyart/`; sidecar provenance is
      kept for regeneration convenience but does **not** include
      `concept_hash` (nothing downstream should be able to key
      conditioning off key art)
- [ ] `concept` mode keeps current behaviour: `assets/src/concept/`,
      `concept_hash` in provenance
- [ ] CLI surface makes the mode an explicit, required choice — no silent
      default that lets a key-art generation land in `assets/src/concept/`
      or vice versa
- [ ] Unit-tested against a mocked ComfyUI backend for both modes
