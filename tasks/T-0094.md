## Context

New task from `docs/HANDOFF.md` Section 4, and the server-side half of
revised T-0066. Implements `docs/design/09-identity.md` Section 1: server
generates a seed phrase, derives the `identity.token` from it, and
**discards the phrase** - only the derived token is ever stored. Loss of
the phrase is final and by design.

## Acceptance

- [ ] `POST /v1/identity` generates a phrase, derives a token, persists
      only the token, and returns the phrase to the caller exactly once
- [ ] Test: derivation is deterministic - the same phrase always yields
      the same token
- [ ] Test: the phrase itself is never present anywhere in the database
- [ ] Test: derivation/mint endpoint is rate-limited (anti-brute-force,
      S-5 open in `docs/design/09-identity.md`)
