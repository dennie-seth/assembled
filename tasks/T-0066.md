## Context

**Revised per `docs/HANDOFF.md` Section 3.** Originally "anon token:
generate, persist, never PII." Now: **seed-phrase derivation** (D-5,
`docs/design/09-identity.md` Section 1). The server generates the phrase,
derives the token, and discards the phrase (T-0094, server side) - this
task is the client half: persist the phrase to a local file on first run,
and load it on subsequent runs to re-derive the same identity.

## Acceptance

- [ ] First run: client requests a phrase from the server and persists it
      to a local file
- [ ] Later runs: client loads the saved phrase and re-derives the same
      identity via the server
- [ ] Test: persistence round-trip
- [ ] Test: regeneration path (what happens if the file is missing) is
      deliberate, not accidental data loss
- [ ] First-run copy states plainly that phrase loss is final
      (`docs/design/09-identity.md` Section 1)
