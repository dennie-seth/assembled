## Context

`07-items-economy.md` §5 (Bleed Timers, "Visual feedback"): bleed
proximity is never shown as a number — same rule as collapse
(`10-time-and-progression.md` §5). Instead, **alpha ramps down as
expiry nears, ending as bare contour/outline just before the item bleeds
away.** Applies to both held and world/escrow-anchored instances. **Same
shader family as chroma** (`05-art-direction.md`) — one parameter, no UI
cost.

Cross-referenced as **A-5** ("Bleed-alpha ramp — held/world timer
proximity, contour-only at expiry", `13-asset-pipeline.md` §7,
`05-art-direction.md`, `GDD-OPEN.md`). Prose dependency: shares its
shader family with T-0121 (chroma) — expect shared plumbing, not a
fully separate shader stack.

## Story

As the client, I want an item's rendered alpha to ramp down toward a
contour-only silhouette as its bleed timer nears expiry, so that a
player reads "this is about to disappear" from the object itself, with
no timer UI.

## Acceptance

- [ ] Alpha ramps down as an item's `bleed_at` (`04-data-model.md` §3)
      approaches, reaching a bare contour/outline-only render
      immediately before the item bleeds away
- [ ] Applies uniformly to both **held** items (60-90 min timer) and
      **world/escrow-anchored** items (48-72 h timer) — same visual
      mechanic, different underlying duration
- [ ] No numeric countdown, timer bar, or other explicit UI element
      accompanies the ramp — the alpha value is the only signal
- [ ] Shares its parameter/shader plumbing with the chroma shader
      (T-0121) rather than introducing an independent shader stack, per
      `05-art-direction.md`'s "same shader family" framing
- [ ] Test: alpha is monotonically non-increasing as time-to-`bleed_at`
      decreases across a representative range
- [ ] Test: at the contour-only end state, only outline/edge pixels
      remain visibly non-transparent
