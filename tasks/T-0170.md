## Context

Users need a visual signal on the Kanban board when a card's dependencies are
all in terminal status (`done` or `retired`), so they know the card is safe to
run without first manually checking each dependency.

Related to the board's existing blocker-count badge feature
(`tools/board/src/client/boardView.js`). The complement is: a card that has
deps and all of them are terminal should be highlighted as "unblocked" —
distinct from a card with zero deps (which was never blocked to begin with).

Also tightens `assertCanMoveToInProgress` in `dependencyGuard.js` to treat
`retired` the same as `done`, since a retired dependency is effectively
complete and should not block a card's progression.

## Acceptance

- [ ] `computeUnblockedIds(tasks)` exists in
      `tools/board/src/client/board.js` and returns a `Set` of task IDs
      whose every listed dependency has status `done` or `retired`
- [ ] A card with at least one dependency and all of them `done` or `retired`
      renders a badge with class `card-unblocked-badge` and
      `aria-label` "All dependencies complete — ready to run" in the board UI
- [ ] A card with at least one dependency that is not `done`/`retired` does
      NOT render a `card-unblocked-badge` element
- [ ] A card with an empty `depends_on` array does NOT render a
      `card-unblocked-badge` (zero deps is not the same as unblocked)
- [ ] `assertCanMoveToInProgress` in
      `tools/board/src/lib/dependencyGuard.js` no longer rejects a move when
      a dependency's status is `retired` (only non-`done`/non-`retired` deps
      count as unmet)
- [ ] `npm test --prefix tools/board` passes with all tests green and ESLint
      clean
