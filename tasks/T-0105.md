## Context

Resolves **V-5** (home palette: colour count + hex values) and **P-A**
(slot count and value-ramp semantics for P-4) — both recorded resolved-
as-a-process in `docs/design/13-asset-pipeline.md` §6, pending this task
actually doing the extraction.

Once a concept sheet is human-approved (T-0104's output, gate 1 of 2 —
`13-asset-pipeline.md` §6), cluster its colours down to N, order the
clusters into a value ramp, and emit a LUT. That LUT is what T-0073's
quantizer (Oklab/CIELAB, dithering off) needs to descend real assets for
this archetype — this task is what unblocks it, per-archetype rather than
via one global palette decision.

Not started until a human has approved the Signal Tower concept sheet
that T-0104 produces.

## Acceptance

- [ ] Given an approved concept sheet, clusters its colours to N (N
      itself is a parameter, not hardcoded — see P-B in
      `13-asset-pipeline.md` §7 for related open tuning questions)
- [ ] Orders clusters into a value ramp with stable, documented semantics
      (P-4: index `N` means palette slot `N` at the same ramp position in
      every asset)
- [ ] Emits a LUT consumable by T-0073's quantizer
- [ ] Deterministic: same input sheet + same N -> byte-identical LUT
- [ ] Unblocks T-0073's quantizer for the Signal Tower archetype
