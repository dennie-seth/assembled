As a user I want to ensure tools/board/node_modules is pre-installed in the worktree so verification agent wouldn't have to run npm install as T-0043 validator suggests.

## Context

The reviewer for T-0043 (and others) noted that fresh git worktrees created
by the Agent Runner lack a `tools/board/node_modules` directory, forcing the
verification agent to run `npm install` before it can execute tests. This
adds friction and risks version drift. The fix is to symlink
`tools/board/node_modules` from the canonical main-worktree installation into
each new worktree at worktree-creation time (`docs/PLAN.md` §Phase 0 →
runner/orchestrator task lifecycle).

## Acceptance

- [ ] `linkBoardNodeModules({ worktreeDir, repoRoot })` is exported from
      `tools/board/src/runner/gitOps.js` and creates a symlink at
      `<worktreeDir>/tools/board/node_modules` pointing to
      `<repoRoot>/tools/board/node_modules`
- [ ] The function is best-effort and idempotent: if the source does not yet
      exist it returns without error; if the destination already exists it
      returns without error
- [ ] `createWorktree` in `gitOps.js` calls `linkBoardNodeModules`
      automatically after creating a worktree
- [ ] `.gitignore` (at repo root or `tools/board/`) excludes the symlink so
      it is never committed
- [ ] Vitest tests for `linkBoardNodeModules` pass (covering: symlink
      created when source exists, silently skipped when source missing,
      idempotent when destination already exists)
- [ ] All existing tests continue to pass (945/945 or equivalent)
