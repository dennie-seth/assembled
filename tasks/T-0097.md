## Context

New task from `docs/HANDOFF.md` Section 4. Implements the `offering` table
(`docs/design/04-data-model.md` Section 3) and the take/withdraw endpoints
(`docs/design/03-net-protocol.md` Section 4). Payment and release must be
one transaction - INV-4 (`docs/design/08-invariants.md` Section 1) requires
there be no observable state where both parties hold, or neither.

**Escrow is the only exchange mechanism in v1** (`docs/design/07-items-economy.md`
Section 7) - reliable and exploit-free, no trust required, no betrayal
possible. The **plea** variant (unlocked item + request, anyone may take
it and walk away, trust-based) is explicitly v2-deferred; do not build
anything here that would make plea "fall out for free" as an unintended
side effect - it ships later as a separately-marked object so players opt
into that vulnerability deliberately.

**Unclaimed offerings expire on the standard 48-72h world/escrow bleed
timer** (`07-items-economy.md` Section 5, `docs/design/10-time-and-progression.md`
Section 2) - there is no separate escrow-specific expiry job to build;
`offering.expires_at` reuses the same bleed machinery every other
world-anchored instance uses.

## Acceptance

- [ ] `POST /v1/offerings/{id}/take` commits both custody changes (payment
      + release) atomically or neither
- [ ] Test: no partial state is observable mid-transaction from a
      concurrent reader
- [ ] Test: both-hold and neither-hold states are provably impossible, not
      just untested
- [ ] Uses the same CAS-on-version guard as T-0095 for the offered item
- [ ] Unclaimed offering past `expires_at` returns to general circulation
      via the standard bleed path, not a bespoke escrow-expiry handler
