## Context

New task from `docs/HANDOFF.md` Section 4. **This is the smallest
meaningful test of the whole economy, and per the handoff's suggested
order it should exist and fail before it passes** - write it before, or
alongside, T-0097's escrow handler and any further item HTTP handlers
beyond T-0095's repo layer.

Scenario (`docs/design/08-invariants.md` Section 1): identity A holds item
X and transfers it away; identity B takes X. Assert A no longer holds X,
assert exactly one holder exists, assert no third identity can also take
X, assert total instance count is unchanged.

Concretely, this exercises the `leave`/`take` pair from
`docs/design/07-items-economy.md` Section 3 and
`docs/design/03-net-protocol.md` Section 3: A calls `leave` (X moves to a
world anchor), B calls `take` (X moves to B's holding). A third identity
C attempting `take` on the same instance after B wins must observe a CAS
conflict, not a partial or duplicate result.

## Acceptance

- [ ] Test implements the full A-leaves-X / B-takes-X scenario above
      end-to-end against real repo/handler code (not mocked custody logic)
- [ ] Assertions cover INV-1 (single custody), INV-2 (no duplication),
      and INV-3 (conservation - count unchanged)
- [ ] This test is written and demonstrably red before the item transfer
      path is complete, then green after
