## Context

New task from `docs/HANDOFF.md` Section 4. Every item custody transfer is
a compare-and-swap on `item_instance.version`
(`docs/design/04-data-model.md` Section 3) - the loser of a concurrent
transfer race fails outright, never merges. This is INV-2
(`docs/design/08-invariants.md` Section 1), and it is not retrofittable
once items are live - get it right here.

## Acceptance

- [ ] `ItemRepo` transfer operation takes an `expected_version` and only
      applies if it still matches, incrementing `version` and
      `custody_depth` atomically on success
- [ ] Test: concurrent transfer attempts on the same instance - exactly
      one wins, the other observes a conflict and does not partially apply
- [ ] Test: `custody_depth` strictly increases, never decreases or resets
      (INV-5)
