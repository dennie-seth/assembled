## Context

Dogfooding on T-0100 (`agent: null`) surfaced this: hitting Run on a card
with no agent assigned does nothing observable -- no plan, no diff, no
error. The card just sits there. Run needs a defined behavior for the
unassigned case instead of a silent no-op.

## Story

As a board user, when I hit Run on a card that has no agent assigned, I
want it to be planned and then executed by a generic/default agent, so
that Run produces real work instead of silently doing nothing.

## Acceptance

- [ ] Running an **unassigned** card (`agent: null`) first invokes the
      planner to expand it into an implementable spec (acceptance
      criteria + touched files) instead of dispatching an empty run
- [ ] After planning, a **generic/default agent** implements the card,
      replacing the current silent no-op / empty-diff outcome seen on
      unassigned or thin cards
- [ ] The Run action gives visible feedback when a card is unassigned --
      it must never silently no-op
- [ ] Known wrinkle: a card whose work is non-code (research/naming,
      e.g. a name-collision check like T-0100) has nothing for the
      reviewer gate to diff against. Such cards must emit a committed
      artifact (e.g. a note under `docs/`) so there's something to
      review, or be typed to skip the code-review gate. T-0110 is the
      cautionary example here: its run FAILed the gate on an empty diff.
