## Context

Round 2 of the T-0099 economy simulation (HANDOFF Section 11.5) could not
answer whether chain-key persistence should be scoped per-run or per-week,
because the sim model has no concept of an identity that outlives a single
run. `01` Section 5 describes collapse as an event an **identity** survives
by starting a new **universe** -- the current sim conflates the two, so
there is nothing in the model that persists across a collapse boundary.
This card is a prerequisite for T-0130 (exit condition), which needs a
persistent identity to attach completion state to.

## Story

As a simulation author, I want the sim model to separate a persistent
**identity** (carries vocabulary + unlock state, survives collapse and
starts a new universe) from a **run** (one universe), so that per-run vs
per-week unlock scoping become distinguishable and later cards can model
identity-level state across collapses.

## Acceptance

- [ ] An identity survives collapse and starts a new universe within the
      same simulation run -- collapse no longer terminates the identity
- [ ] Vocabulary and unlock state are modelled as identity-level state,
      distinct from universe/run-level state
- [ ] Per-run-scoped and per-week-scoped unlock decay become
      distinguishable configurations in the sim, where previously they
      were indistinguishable
