### Root-cause analysis (planner investigation)

The 29 FAILs across 12 cards fall into three dominant categories:

**Category A — Uncommitted implementation (7 occurrences, 5 cards).**
T-0110 (1 FAIL: "zero commits were made"), T-0129 first FAIL ("Implementation
is NOT committed — config.py, engine.py, types.py changes exist only as
unstaged working-tree modifications"), T-0131 (2 FAILs: "Implementation not
committed … exists only as unstaged working-tree changes"), T-0132 (2 FAILs:
"three files are not committed … untracked (never git-added)"). The
implementer agent writes code but does not `git add` + `git commit` before
handing off to validation. The existing `tdd` skill and `conduct.md` both
say to commit, but nothing machine-checks that HEAD differs from the merge
base before the reviewer runs.

**Category B — Reviewer permission/environment gaps (9 occurrences, 4
cards).** T-0043 (4 FAILs: "docker command not found", then 3× "Bash
permission system denied every attempt to set DATABASE_URL"), T-0072 (1
FAIL: permission denied), T-0132 (1 FAIL: "pip install … denied by the
permission system"), T-0141 (4 FAILs: "npm test … denied by the Bash
permission system"). The reviewer agent cannot run the verification commands
its own checklist requires — the grant strings in `.claude/agents/reviewer.md`
or the worktree environment are missing the tools the `verifyRouter.js`
routes need. These are infra/config issues, not implementer mistakes.

**Category C — Lint not run before handoff (11 occurrences, 4 cards).**
T-0129 (10 FAILs for ruff I001 — the implementer kept editing pyproject.toml
config instead of running `ruff check --fix` on the actual file), T-0131
(1 FAIL for ruff E501), T-0132 (1 FAIL for ruff E501), T-0136 (1 FAIL for
8 ruff errors). Implementers do not run the linter before handing off, or
attempt fixes that do not resolve the issue.

**Highest-impact fix:** Category A (uncommitted work) is the most
structurally fixable — a pre-validation guard in the orchestrator that checks
`git diff develop...HEAD --stat` is non-empty before launching the reviewer
would catch every Category A FAIL at zero LLM cost. Categories B and C are
also addressable (wider reviewer grants; a lint pre-check in `verifyRouter.js`
or the implementer's own `verify` skill) but are lower bang-per-buck for this
card.
