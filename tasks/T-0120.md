## Context

`18-first-run.md`, full doc. Trigger & sequence (§1): New Game -> identity
created (`POST /v1/identity`) -> phrase-reveal screen (unskippable) ->
offline notice if unreachable -> drop into the calm entry room.

**Phrase moment (§2):** the client auto-saves the phrase to a plain text
file in the local save directory the instant it's returned — no manual
export, no clipboard dependency (**S-3 resolved**, §9). Full-screen,
unskippable, and requires **explicit acknowledgment** (not a dismissible
"Continue") that the player has read and registered what it means —
names both endings explicitly (losing the phrase vs. letting the
universe collapse, `09-identity.md` §3a).

**Clock explanation (§3):** order matters — calm exploration first (a
few minutes, matching the vertical slice's Ground-Relay-style entry,
`14-vertical-slice.md` §10), *then* the one-time chroma explanation. The
player needs to have seen the "normal" palette before being told it will
drift. No numbers, ever.

**Offline signaling (§4), three moments:** pre-play (unmissable notice,
blocks continuing until acknowledged, same weight-class as the phrase
screen but a warning rather than a rite), during play (small persistent
non-diegetic indicator — the one deliberate exception to the no-HUD
aspiration), and session-end-still-offline (a recap reminder that
nothing from the session was saved).

Prose dependency: this needs `POST /v1/identity` (T-0094) to exist to
trigger the phrase moment.

## Story

As the client, I want the first-run sequence to auto-save the seed
phrase, force explicit acknowledgment of what it means, signal offline
state at every relevant moment, and explain the collapse clock only
after a calm baseline exploration window, so that a new player never
loses a universe to a failure mode the design already knows how to
prevent.

## Acceptance

- [ ] New Game triggers `POST /v1/identity`, and the returned phrase is
      auto-saved to a local file **before** the phrase-reveal screen is
      shown to the player — no manual save/export step exists
- [ ] The phrase-reveal screen is full-screen and unskippable, and
      requires an explicit acknowledgment action (not a generic
      dismiss/continue) before the client proceeds
- [ ] The acknowledgment screen names both loss modes distinctly: losing
      the phrase (everything gone) vs. letting the universe collapse
      (that universe's unlocks/held items gone, phrase and vocabulary
      kept)
- [ ] Pre-play offline notice blocks continuing until acknowledged if
      the server is unreachable at launch
- [ ] A persistent, non-diegetic offline indicator is shown during play
      whenever the server is unreachable
- [ ] A session-end recap fires if the session ends while still offline,
      stating that nothing from it was saved
- [ ] The chroma/clock explanation fires exactly once, only after a
      baseline exploration window in the calm entry room has elapsed —
      never before the player has seen the un-drifted palette, and never
      showing a number
- [ ] Test: skipping/dismissing the phrase screen via any input other
      than the acknowledgment action is not possible (no escape/back
      path that bypasses it)
