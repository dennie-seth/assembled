## Context

`15-server-ops.md` §2 names this component explicitly: **"Sweep worker |
exactly 1 per shard | Bleed, spawn, collapse, retention, census (`04`
§7)"** — with a hard callout that the sweep singleton is the scaling
constraint: two workers processing one bleed can duplicate an item
*inside* the worker, where CAS (INV-2) cannot see it. Advisory lock +
`FOR UPDATE SKIP LOCKED` is the named mechanism; leader election is the
deployment requirement (**OPS-4**, §8, still open).

**Doc gap worth flagging:** `15` §2 cites `04-data-model.md` §7 for the
sweep worker's data-model needs, but `04-data-model.md` currently only
runs to §6 (Cross-References) — there is no §7. The individual pieces
the worker touches exist elsewhere in `04` (item `bleed_at`, §3;
`identity.collapse_expires_at`, §1) but nothing currently documents
retention/census schema. Worth raising back to whoever owns `04` rather
than inventing a §7 here.

Retention here means transfer-receipt retention (T-0126, 72h) — this
worker is the natural place to expire them, not a separate cron.

## Story

As the server, I want a single per-shard sweep worker that performs
bleed (landing roll + recipient selection), collapse, receipt retention,
and census, so that these mutating background jobs never run twice
concurrently against the same shard.

## Acceptance

- [ ] Exactly one sweep worker instance is active per shard at a time,
      enforced by an advisory lock
- [ ] Bleed processing uses `FOR UPDATE SKIP LOCKED` when selecting
      candidate rows, so a losing worker (in a future multi-node
      deployment) skips rather than blocks or double-processes
- [ ] Bleed: expired `item_instance` rows (`bleed_at` passed,
      `04-data-model.md` §3) get a landing roll and recipient selection
      per `07-items-economy.md` §4/§5
- [ ] Collapse: identities past `collapse_expires_at`
      (`04-data-model.md` §1) are processed per `10-time-and-progression.md`
      §5
- [ ] Receipt retention: transfer receipts (T-0126) older than 72h are
      purged by this worker
- [ ] Census: current population count is produced/updated, feeding V-9
      variant-eligibility gating (T-0123) and shard population
      (`15-server-ops.md` §3)
- [ ] Test: two worker processes started against the same shard — only
      one performs work; the other's lock attempt is a no-op, not an
      error
- [ ] Test: a bleed row already claimed by one worker is skipped, not
      blocked on, by a concurrent worker
