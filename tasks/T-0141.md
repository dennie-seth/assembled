When side-menu appears, text in cards doesn't scale properly and overlaps neighbour cards. As a user I want side-menu to cover cards and scroll right and left to see them properly once necessary.

## Context

The board's `#side-panel` is `position: fixed` and overlays board columns.
A previous fix added `padding-right: 29rem` to `body` when the panel was
visible, intending to prevent the overlay from obscuring columns. This
caused `.column` (formerly `flex: 1 1 0; min-width: 12rem`) to compress
as the effective viewport shrank, squeezing card text until it overflowed
and overlapped neighbouring cards.

The correct fix removes that body padding-right rule entirely: the
side-panel already overlays and does not participate in normal flow, so
no layout side-effect is needed. Columns instead use `flex: 1 0 14rem`
(shrink 0, basis 14rem) so they cannot compress regardless of viewport
width, and the board's existing `overflow-x: auto` lets users scroll
horizontally to reach any column that the overlay covers.

## Acceptance

- [ ] `.column` CSS has `flex-shrink: 0` — columns never compress when the side-panel is open
- [ ] `.column` has a `flex-basis` of at least 100 px (14 rem at default font size) so card text is never squeezed to nothing
- [ ] `#side-panel` CSS is `position: fixed` — it overlays the board rather than pushing columns
- [ ] `body:has(#side-panel:not([hidden]))` no longer adds `padding-right` — the board layout is unaffected by panel visibility
- [ ] `.board` has `overflow-x: auto` so all columns are reachable by horizontal scrolling when the panel overlays them
- [ ] All four assertions in `tools/board/test/client/columnLayout.test.js` pass
