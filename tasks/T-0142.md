As a user, when the side-panel is open and overlays the board, I want to scroll the board both left and right and reach/read every column and card -- including ones behind the panel -- so no card is ever permanently hidden, regardless of how many columns exist.

## Context

T-0141 (PR #87) fixed columns being squeezed/overlapping when the side-panel opens, and relied on the board's pre-existing `overflow-x: auto` for horizontal scrolling. That leaned on overflow that only appears when there happen to be enough columns to exceed the viewport width. It did not guarantee bidirectional reachability: with few columns the board doesn't overflow at all, so the last column sits permanently hidden behind the fixed, overlaying side-panel with nothing to scroll toward. This card closes that gap.

The fix must ensure the board's scrollable content genuinely overflows (or otherwise reserves/exposes space) whenever the side-panel is open, for any number of columns -- not just rely on there already being enough columns to overflow naturally.

## Acceptance

- [ ] With the side-panel open and few columns (fewer than would naturally overflow the viewport), the last column is still fully reachable and readable by scrolling right -- not permanently hidden behind the panel
- [ ] With the side-panel open and many columns, all columns remain reachable by scrolling both left and right (no regression from T-0141)
- [ ] Behavior is verified by an observable assertion (e.g. scrolling reveals the target column's content is not covered/clipped by the panel), not merely that a CSS overflow property is present in the stylesheet
- [ ] Works regardless of column count -- test covers at least one low-column-count case and one high-column-count case

References T-0141 (PR #87), which fixed column squeezing but left this scroll-reachability gap for low column counts.
