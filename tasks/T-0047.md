## Context

`POST /v1/notes/{id}/rate {val: +1|-1}`. One vote per `(note_id, voter)`,
idempotent - resubmitting the same value is a no-op, changing it overwrites
the prior vote. This is the base rating mechanism; T-0098 layers the
proof-of-play gate on top of this endpoint.

**A well-rated note slows the author's held-bleed timer**
(`docs/design/02-notes-system.md` Section 7, `docs/design/07-items-economy.md`
Section 5) - this endpoint's write path should update whatever the
author's current bleed-timer multiplier/curve is, not just `notes.score`.
Exact curve is open (N-1); implement `score` first and leave a clear seam
for the bleed-timer hook rather than hardcoding a guess. This benefit is
**held bleed only** - it must never touch `identity.collapse_expires_at`
(`docs/design/10-time-and-progression.md` Section 5) - a prolific solo
player extending their own collapse clock indefinitely is the exact
permanent-lockout hole that clock exists to close.
