As a user I want bottom tasks which don't fit into the view to render gradually in batches, so the board stays performant as task count grows. I also want a "go up" button to immediately scroll to the top.

## Context

The Kanban board (`tools/board`) renders every card in every column on each `renderBoard` call. As the backlog grows beyond dozens of tasks, this becomes an unnecessary DOM cost — cards below the fold are not visible and don't need to exist yet. This optimisation adds IntersectionObserver-based lazy loading (batched column rendering) so only the first `BATCH_SIZE` cards per column are in the DOM initially; scrolling to the bottom of a column loads the next batch automatically. A fixed "Go up" button is also added so the user can return to the top of the page without scrolling manually when the board is long.

Reference: `docs/PLAN.md` Phase 1 (board tooling) performance concerns; `tools/board/src/client/boardView.js`.

## Acceptance

- [ ] `BATCH_SIZE` is exported from `boardView.js` with value `20`; columns with more than `BATCH_SIZE` cards render only the first `BATCH_SIZE` cards in the DOM initially (confirmed by inspecting `renderColumn` in `boardView.js` and the test that verifies only 20 of 25 cards appear without a sentinel trigger)
- [ ] A `div.batch-sentinel[data-status]` element is appended inside the column's card list when the column has more cards than the current visible count, and is absent when all cards fit in the current batch (confirmed by test asserting sentinel presence/absence)
- [ ] An `IntersectionObserver` is set up after each `renderBoard` call; when a `.batch-sentinel` enters the viewport the observer calls `onShowMore(status)`, which increments the column's visible count by `BATCH_SIZE` and re-renders (confirmed by test that triggers the observer callback and checks more cards appear)
- [ ] `initGoUpButton` in `goUp.js` hides `#go-up-btn` when `scrollY < 200` and shows it when `scrollY >= 200`; clicking the button calls `scrollTo({ top: 0, behavior: 'smooth' })` (confirmed by unit tests for `goUp.js`)
- [ ] All existing and new Vitest tests pass; ESLint reports no errors
