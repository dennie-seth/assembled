## Fix

Added `checkEdgeCasesPreflight` (`tools/board/src/runner/edgeCasesPreflight.js`),
a warn-only pre-flight mirroring `impossibleAcceptancePreflight.js`'s
contract exactly: given a task, if its `## Acceptance` section has
checklist items but no bold `**Edge cases:**` line before the next
heading, it returns one warning string; otherwise (no Acceptance section
at all, or a well-formed Edge cases block already present) it returns no
warnings. Never blocks a run -- a false positive here must not stop a
legitimate card, same reasoning `impossibleAcceptancePreflight.js`
documents for its own warn-only shape.

Wired into `runOrchestrator.js`'s existing pre-flight chain
(`_runCardInWorktree`), immediately after the impossible-acceptance
preflight, using the same `_log*Warning` pattern: a run-log event plus an
`assembled-board`-authored card comment, so both a live watcher and a
later human reader see it. This surfaces the gap the moment a card without
an Edge cases block is dispatched, rather than leaving it silent until the
reviewer (or nobody) notices partway through implementation.

**Round 3 correction:** the first two rounds only checked for the bold
`**Edge cases:**` label's presence. `.claude/rules/planner.md` (lines
100-123) requires more than the label -- the block must be "followed by
its own `- [ ]` checklist items, one per edge case." A card with a bare
`**Edge cases:**` label and nothing underneath (or only prose, no
checklist items) satisfied the old regex and was silently treated as
compliant, which contradicts the exact convention this preflight exists
to enforce. `checkEdgeCasesPreflight` now also scans forward from the
label (bounded by the same next-heading cutoff) for at least one `- [ ]`
item, reusing `acceptanceCriteria.js`'s existing `CHECKBOX_RE` (now
exported) rather than duplicating that pattern. Three new tests in
`edgeCasesPreflight.test.js` cover: label with nothing after it before the
next heading, label followed only by non-checklist prose, and label
followed by prose then a checklist item (still credited, no false
positive on intervening explanatory text).
