## Context

`17-localization.md` §2 (The Type Split): **"`LocId` and display text are
different types. An ID cannot be rendered; display text cannot be sent
over the wire or written to the database."** A thin POD-integer wrapper
in the GDExtension with no `to_string()` — resolution happens only
through the translation layer, turning a missed-localization bug into a
compile error instead of a raw `47` showing up on screen in a shipped
build. This also solves the seed-phrase non-localization requirement
(`09-identity.md` §1) for free: phrase words are identifiers under the
type split, structurally exempt rather than exempt by convention.

`17` §3 (Build Checks) — same class as INV-12 and P-4, a declared set
verified at build time:

| # | Check |
|---|---|
| L-1 | Every `LocId` in the catalogue resolves in every **shipped** locale — missing key fails the build |
| L-2 | Every locale's template declares the **same named slot set**; reordering allowed, adding/dropping/renaming a slot is not |
| L-3 | No locale contains a positional (vs. named) format placeholder |
| L-4 | The seed-phrase wordlist has exactly one form and is absent from every translation catalogue |

A locale under construction is marked incomplete and excluded from the
build rather than failing it (otherwise L-1 blocks starting any new
translation).

## Story

As the client, I want a `LocId` type that cannot be mistaken for display
text, and build-time checks that catch missing/mismatched/positional
localization content, so that a localization bug is a build failure, not
something a player sees on screen.

## Acceptance

- [ ] `LocId` wrapper exists in the GDExtension as a POD integer type
      with no implicit or explicit `to_string()` / string conversion —
      resolving to display text is only possible through the
      translation layer
- [ ] **L-1:** build fails if any catalogued `LocId` is missing from a
      shipped locale's compiled `.translation` resource
- [ ] **L-2:** build fails if a locale's template declares a different
      named-slot set than the reference (English) template for that
      `template_id` — reordering the slots is allowed, adding/dropping/
      renaming one is not
- [ ] **L-3:** build fails if any locale string contains a positional
      placeholder (e.g. `{0}`) instead of a named one
- [ ] **L-4:** build fails if the seed-phrase wordlist appears in any
      translation catalogue, or exists in more than one form
- [ ] A locale still under construction (explicitly marked incomplete)
      is excluded from L-1's scope rather than blocking the build
- [ ] Test: each of L-1 through L-4 has a fixture that currently fails
      the check and a fixture that currently passes it
