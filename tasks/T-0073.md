## Context

**Blocked on V-5** (`docs/design/05-art-direction.md` Section 5) — the
home palette's exact colour count and hex values weren't decided yet, and
the palette-quantize step needed them. **V-5 is now resolved as a
process**: the palette is extracted from an approved concept sheet via
T-0105 (cluster → value ramp → LUT), which unblocks the quantizer.

The descent chain per `docs/design/13-asset-pipeline.md` §3.1:
```
generate (SDXL + style LoRA, integer multiple of target)
  -> BiRefNet cutout (props/characters only, before descent)
  -> box/area downscale (exact integer factor)
  -> quantize to locked palette (Oklab/CIELAB, dithering OFF)
  -> cleanup (orphan pixels, edge repair)
  -> validate (§2)
  -> commit sprite to assets/final/
```

**No upscale step.** The pipeline descends from generation resolution to
native tile size via box/area averaging (preserves the most information
for the quantizer). Nearest-neighbour aliases; Lanczos rings produce halos
that quantize into visible garbage. Real-ESRGAN is not part of this chain.

The palette **family** is already fixed even though the exact hex set
isn't (`05-art-direction.md` Section 3) - the quantize step should target
this family once V-5 lands:
- Concrete greys (the structural base, widest range)
- Oxide and rust (the only warm notes)
- Institutional green and ochre (interiors, corridors)
- Deep shadow (near-black, not black)

Foreign-universe items/entities render in a *different* palette entirely
(`origin_palette`, chroma-as-distance-from-home, `01-vision.md` Section 8)
- this task's quantize step is for the **home** palette only; foreign
chroma is a separate per-instance shader concern (A-4, not this task).
