## Context

New task from the canonical Notion pipeline doc, which resolves V-5 (the
home palette) as a *process* rather than a fixed hex list: the palette is
extracted from an approved concept sheet, not invented ahead of it
(`docs/design/13-asset-pipeline.md` §6). That means art generation for an
archetype now starts with a concept step, before any recipe exists.

Concept art is a **source**, not output — the opposite of P-1/P-3 for
every other asset in this pipeline. It is full-colour, full-res, **never
indexed or quantized** (there is no palette yet to quantize against), and
it **is committed** to `assets/src/concept/` because the palette
extraction (T-0105) and the archetype's later conditioning (T-0106) both
read back from it.

Reuses `tools/comfy-client`'s `ComfyUIClient`/pipeline plumbing (T-0071) —
this is a distinct "concept" mode that skips the descent/validate arm
entirely (no box downscale, no palette quantize) rather than a new
generation stack.

First subject: the **Signal Tower** vertical-slice archetype
(`docs/design/14-vertical-slice.md`).

## Acceptance

- [ ] Given a concept recipe (prompt + seed + model hash + dimensions),
      generates a full-colour, full-res sheet via base SDXL through the
      shared `comfy-client`/`gen-client-base` plumbing (license-allowlist
      gate included)
- [ ] Output is written to `assets/src/concept/` (committed, not
      gitignored) — never indexed/quantized, never downscaled
- [ ] Captures provenance (model + license + prompt + seed +
      `concept_hash`) alongside the output, matching the existing
      provenance-seam pattern
- [ ] CLI entrypoint to run a concept generation from a recipe file
- [ ] Unit-tested against a mocked ComfyUI backend — no live SDXL call in
      the test suite
- [ ] First real output: an approved Signal Tower concept sheet, used to
      unblock T-0105
